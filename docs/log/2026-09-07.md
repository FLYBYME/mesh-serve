## The recurring failure: `stale`

Hit for the third time today. It is not a bug in one place, it is a design
consequence, and it needs to stop being manual.

**What happens.** A generated client bakes one `shapeHash` covering the site's
**whole** exposure. Add any contract anywhere — `site.create`, `cdn.site_edit`,
`node.provision` — and that hash moves, so **every deployed part is instantly
stale**, including parts that do not use the new contract and could not care that
it exists. The catalog browser breaks because the fleet gained a call.

The manual fix is: regenerate the client, bump every API-facing part, publish,
build, compose, deploy. Six steps, and I have run them five times today.

**Three fixes, in order of value:**

1. **Staleness should be per call, not per exposure.** *Did any call I use
   change shape?* — not *did the exposure change at all?* Adding a contract would
   then invalidate nothing, and changing one would invalidate only the parts
   using it. This removes the failure rather than reporting it better.
2. **`cdn.compose` should refuse a stale part**, naming it. A release that will
   fail in front of a person should not be composable. Fail at compose, where
   somebody is looking.
3. **A stale client should refetch the descriptor and recover.** #47 landed
   *reporting* what moved; recovery is still manual.

Until (1), every contract addition costs a full rebuild of every part.

## Done today

**Security — a live hole, found by pointing a node at the internet.** A process
with no `MESH_KEY` dialled surf's mesh port, became a peer, and read `user.find`
and `apiToken.find`. Empty only because that database was empty. `WSTransport`
held the key and never checked it, and separately ignored its bind host, so
loopback-only was not achievable at all. Fixed in mesh `2.4.1`; verified against
the real machine — no key now gives `PEERS=0`, correct key connects.

**⚠ The Atlas password is burned.** The startup banner printed the full URI into
surf's journal on first boot. The banner is fixed; the credential needs rotating.

**The fleet is real.** `surf.surfdns.net` and this laptop on one mesh, one
database. Supervisor mounted so assignment has something to switch; groups stored
by reference so a group edit rolls; placement so a build stops being offered to a
981MB box; `node.status` now reports observed state for every node rather than
only the one asked about.

**Configuration is a file.** `bin/node.mjs` reads `./.env` or
`/etc/mesh/node.env`, and the banner says which. No secrets on a command line —
an argument is visible in `ps` to every user on the box. `.env` is now gitignored;
it was not.

**Two checkouts, deliberately different.** `~/code/mesh-serve` for editing and
tests against local mongo; `~/code/mesh-live` joined to the real fleet and started
with exactly the command a VPS uses.

**`docs/operating.md` rewritten** for somebody sitting on the machine.
