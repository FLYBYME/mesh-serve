## The recurring failure: `stale`

Hit for the third time today. It is not a bug in one place, it is a design
consequence, and it needs to stop being manual.

**What happens.** A generated client bakes one `shapeHash` covering the site's
**whole** exposure. Add any contract anywhere — `site.create`, `cdn.site_edit`,
`node.provision` — and that hash moves, so **every deployed part is instantly
stale**, including parts that do not use the new contract and could not care that
it exists. The catalog browser breaks because the fleet gained a call.

The manual fix is: regenerate the client, bump every API-facing part, publish,
build, compose, deploy. Six steps, and I have run them five times today.

**Three fixes, in order of value:**

1. **Staleness should be per call, not per exposure.** *Did any call I use
   change shape?* — not *did the exposure change at all?* Adding a contract would
   then invalidate nothing, and changing one would invalidate only the parts
   using it. This removes the failure rather than reporting it better.
2. **`cdn.compose` should refuse a stale part**, naming it. A release that will
   fail in front of a person should not be composable. Fail at compose, where
   somebody is looking.
3. **A stale client should refetch the descriptor and recover.** #47 landed
   *reporting* what moved; recovery is still manual.

Until (1), every contract addition costs a full rebuild of every part.

with no `MESH_KEY` dialled surf's mesh port, became a peer, and read `user.find`
and `apiToken.find`. Empty only because that database was empty. `WSTransport`

it was not.

## Nine bugs, and the shape they share

Almost none of them failed. They **succeeded at something slightly wrong**, which
is why each took longer to find than to fix.

1. **`release` had no `scopedBy`** while its own comment explained why reads were
   safe *because* it did. `release.find` returned every tenant's compositions.
   The comment was correct about the rule, which is what made reading the file
   reassuring.
2. **A CRUD event's delivery scope *is* its collection's `scopedBy`.** So the same
   missing line meant 15 of 18 granted events could be narrowed to nobody: the
   stream opened, the subscription succeeded, the list never updated.
3. **Scoping `release` broke serving.** `site` is scoped and `cdn.resolve_site`
   exists precisely because a browser is anonymous — `release` never grew that
   second door. Three reads needed the site's tenant; I fixed two and missed
   `api.describe`, whose `.catch` turned the refusal into *this site has no
   release*, so `/_describe` answered with **no calls** and every contract looked
   changed. That is what "everything says stale" actually was.
4. **`operator` was checked everywhere and existed nowhere.** `gate.ts` resolves
   `auth: 'operator'` against that exact key and every fleet handler calls
   `requireOperator`, but no role row was ever created — so granting it threw out
   of `onStart` and systemd restarted the node into the same crash. A line in an
   environment file turned the platform off.
5. **`npm install` served a cached git dep** and said "up to date". surf ran mesh
   **2.4.0** — the version where `WSTransport` holds `MESH_KEY` and never checks
   it — on a public `0.0.0.0:4001`. The lockfile's *spec* said 2.4.1 while its
   resolved SHA said 2.4.0, and npm honours the SHA. `npm update` is what
   re-resolves a git dependency. Third time today.
6. **A build needs 70MB, not 2048.** Measured: clone mesh-core, bundle four
   parts, flat 70MB peak, because esbuild is a Go binary outside node's heap. The
   guessed number meant surf refused every build, and the answer to *bundle 30KB
   of TypeScript* became *provision a second machine*. The incident the constant
   was written after was `node.hello` ignoring groups, and that was fixed long ago.
7. **The RPC default is 10s; `release_repo` takes 22.** The caller timed out while
   the builder finished every part correctly — the run failed, the work succeeded,
   nothing said so.
8. **`--org-slug` defaulted to `tim-org`.** On an empty cluster, harmless. On a
   real one it created a second organization, made every `catalog.declare` answer
   *No such part*, and — quietly — gave the account two memberships, which makes
   the scope ambiguous, which makes the `authorize` hook decline to guess, which
   makes every *scoped* collection answer 401 while the global ones keep working.
   That reads as an auth bug and is a membership bug.
9. **mesh-core's `@flybyme/mesh-serve` was a copy from Sep 6.** `file:` gave a
   copy rather than a link, so regenerating the client could not see a single
   contract added since. "Declared and not exported" was the only symptom.
