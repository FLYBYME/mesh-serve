THE TASK
================================================================================

Serve the exposure descriptor at run time, and make the gate real data rather
than a comment.

This is roadmap **B13** and it is specified in `mesh-web/spec/schema-driven-ui.md`
(read §1, §3.1 and §5 — they are short, and §5 is the reason the security shape
is what it is). Everything you need already exists; nothing here is a new
subsystem.

--- 1. The endpoint ---------------------------------------------------------

`GET /api/_describe` returning the `ExposureDescriptor` this site already
computes. Decide and state in your plan:

  * **The gate on it.** It lists what the site exposes and at what level. That
    is not a secret in any useful sense — the routes are already discoverable by
    trying them — but it is a map. Pick `public` or `user`, say why in a comment
    in the code, and note it in your PR. Either is defensible; an undecided one
    is not.
  * **Cache headers.** The document changes only when the site's exposure
    changes, and there is already a hash for exactly that.

It MUST carry `shapeHash`, NOT the exposure hash. `mesh-web/src/net/api.ts` and
`src/net/client.ts` document why: a client asking *"is my rendering stale?"* is
asking a site-independent question, and the exposure hash answers a different
one. Getting this backwards is the bug that was fixed on 2026-09-06; do not
reintroduce it.

Deny-by-default is inherited, not re-implemented: `describeExposure` already
refuses to publish a contract mesh marks `internal` unless `allowInternal`.
`_describe` MUST NOT set `allowInternal`. A descriptor that lists internal
contracts is a worse leak than the endpoint itself.

--- 2. The gate stops being a comment ---------------------------------------

`mesh-core/src/generated/api.ts` currently records the gate only inside a JSDoc
line (`* GET /parts — auth: public`), and that text is **wrong**: the console
site declares `auth: 'user'` for all eighteen of its contracts except
`identity.ticket_issue`. Nothing can detect the drift because the value is not
data.

Emit the gate as a runtime field on the call in the generated client, so
`ApiSpec` carries it and a page can read it. `ApiCall.types` stays a phantom —
this is a *value*, not a type. Keep the emitted shape structural, per
`net/api.ts`'s rule: **never `z.infer` across a package boundary.**

Regenerating mesh-core's client is NOT part of this PR — it is a different
repository. Say in your closing comment that it needs regenerating, and what
will change when it is.
