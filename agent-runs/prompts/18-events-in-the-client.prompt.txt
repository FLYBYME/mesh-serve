================================================================================
THE TASK
================================================================================

A generated client never declares any events, so no collection in any console
is ever live, so every list has a refresh button next to it. That is the whole
bug and both halves around it already exist:

  * SERVER: `/events` is real. `src/api/methods/stream.ts` opens an SSE stream,
    re-resolves the caller on every heartbeat (a stream outlives its
    authorisation), and `decideDelivery` in `src/api/methods/delivery.ts`
    narrows each payload to each subscriber. `src/api/methods/events.ts` builds
    the exposed event table from the site record.

  * CLIENT: mesh-web 0.15.10 reads `ApiSpec.events` and `isCollectionStreamed`
    (`src/net/api.ts` in that repo) and applies `${name}.created|updated|deleted`
    to a live collection.

  * MISSING: `src/api/methods/client.ts` emits `defineApi({ ... })` with
    `calls` and `shapeHash` and NO `events` key. Look at the emitter around
    line 77-124. `isCollectionStreamed` therefore answers false for everything.

WHAT TO DO

Emit `events` for the CRUD collections the site actually exposes, derived from
the same site record and event table the stream uses — never a hand-written
list, and never every event the node knows about. A collection the site does
not expose must not appear. If the subscriber's scope could never have an event
narrowed to it, declaring it promises a stream that will stay silent, which is
worse than declaring nothing.

Decide, state in your plan comment which you chose and why, and keep going: the
generated `events` entries may be bare strings or `DescribedEvent` objects.
Read what mesh-web actually accepts (`node_modules/@flybyme/mesh-web/dist/net/api.d.ts`)
rather than guessing.

WATCH OUT FOR

  * The shapeHash. It is generated beside this and it is NOT yours to change —
    a separate rework is moving where its inputs come from. If adding `events`
    would alter the hash, say so in a comment before you do it.
  * `test/api/` has the generator's tests. A generated file is compared as text
    in places, so expect to update fixtures — update them, do not loosen the
    assertions.

VERIFY IT FOR REAL

A unit test that asserts the emitter wrote a key is not evidence the stream
works. Stand a node up against a local mongo, generate a client for a site that
exposes a CRUD collection, and show an event arriving: write to the collection
