--- 1. Observed state for every node, not just the target -------------------

`src/fleet/methods/node.ts`, in the fleet summary:

    runningServices: host === targetHostname ? runningServices : [],
    provisionedServices: host === targetHostname ? provisionedServices : [],

Only the target's Supervisor is asked. Every other machine is reported running
nothing — and the console draws it, so a machine running three services shows as
connected and empty. That reads as *joined and failed to start anything*, which
is the precise confusion this console exists to end.

Query each connected node's Supervisor.

  * **One slow or wedged node must not stall the report.** Same rule
    `node_reconcile` already follows: gather what you can, say per node what you
    could not. Bound it — a fleet report that waits on a dead machine is a fleet
    report nobody gets.
  * **"I could not ask" is not "it is running nothing."** They are opposite
    diagnoses and must look different in the output. Add a field rather than
    overloading an empty array.

--- 2. Placement: stop treating a Chicago VPS as equivalent to the laptop ----

`builder.build_start` round-robins across every node mounting `builder`. When
surf joined, half the builds went to a **981MB box in Chicago over a home
connection** rather than the 32GB machine holding the blobs. Deploys stopped
finishing, and the failure was a **timeout** — no error, no fallback, no
indication which machine took the job.

Smallest thing that fixes that. At minimum:

  * a service can declare what it wants — memory, and whether it prefers the node
    already holding the data
  * a caller can say *prefer local* for work that is cheap locally and expensive
    remotely, which is every build
  * a node can **decline** work it cannot do, rather than accepting and timing out

**Do not build a scheduler.** No bin-packing, no priorities, no queue. The
smallest mechanism that stops the interchangeability assumption, and it should be
legible in one sitting.

State in your plan where the declaration lives. A contract already declares
`dependencies`; requirements are the same kind of fact and probably belong in the
same place rather than in a new file that has to be kept in step.
