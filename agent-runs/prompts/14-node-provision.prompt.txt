THE TASK — `node.provision`, and nothing else
================================================================================

**One contract.** Items 1 and 3 of the issue are merged already. Do not touch
groups, reconcile, `requireOperator`, or the runner.

A node can be told to acquire a service it does not have: clone or pull a
repository, install it, and register a Supervisor manifest entry pointing at it.

**No new loading mechanism is needed.** `SupervisorServiceEntrySchema.path` is
*"where to dynamically `import()` the compiled service module from — resolved
relative to the manifest file's own directory if not absolute."* Absolute paths
already work. A cloned repository at a known path is a valid manifest entry.

--- Keep the two verbs apart -----------------------------------------------

  * `node.assign` is a **switch**: which of the services a node already carries
    are running. Merged, working, not yours.
  * `node.provision` **makes new switches exist**.

Collapsing them makes "what can this node run" and "what is it running" one
confused thing, and `node.status` stops meaning anything. `node.status` should
grow a list of what is *provisioned* alongside what is desired and running —
that is the one change to existing code this task justifies.

--- Two requirements. Ship neither half-done ------------------------------

  * **A ref, not a branch.** A pinned commit or tag, required in the input. A
    node that pulls `main` changes behaviour when somebody else pushes — the
    mutable-version problem in a new place, and the catalog already refuses it.
  * **`npm i` runs arbitrary install scripts**, so this is a remote code
    execution primitive on every machine we own. It needs BOTH:
      - the `operator` gate (`requireOperator` — follow how assign and reconcile
        use it; note `hello` is a deliberate exception and its comment says why)
      - an **allowlist of repositories**, from the environment, not from input
    If you cannot do both properly, implement neither and say so in your closing
    comment. An unguarded provision is the worst thing that could be added to
    this repository.
